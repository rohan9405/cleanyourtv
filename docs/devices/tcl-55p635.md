# TCL 55P635: keep stock controls with the reference launcher

Single-session report from a TCL 55P635, G07 platform, Android TV 11 with Google TV
Home, firmware `V8-R51AT01-LF1V138` (Android build `RP1A.200622.001`). Tested on
2026-10-24 using the reference launcher v2.7, built from commit `538d260` with
changes to `launcher/app/src/main/res/values/config.xml` only.

This is a launcher configuration and recovery note, not a tested debloat list.
All packages disabled during this session were re-enabled. The related
[G07 list](../../examples/tcl-g07-google-tv/debloat.txt) describes other firmware
and different choices; its package changes were not retained on this unit.

## Stock controls and recovery

After the initial package changes, the owner reported that the settings popup,
Google TV profile button and TV/channel controls did not work as expected.
Restoring the changed packages and stock Home brought the controls back; the
owner confirmed TDT/CH, LIST, INFO, settings and profiles with the physical remote.
The packages were restored together, so this does not isolate which package was
responsible for each symptom.

The restored group was `com.google.android.apps.tv.launcherx`,
`com.google.android.tungsten.setupwraith`, `android.autoinstalls.config.google.gtvpai`,
`com.google.android.feedback`, `com.tcl.dashboard`, `com.tcl.esticker`,
`com.tcl.guard`, `com.tcl.messagebox`, `com.tcl.partnercustomizer`,
`com.tcl.tv.tclhome_passive` and `com.tcl.waterfall.overseas`. This records the
rollback, not a list to disable. The TV player `com.tcl.tv` and input provider
`com.tcl.tvinput` were not disabled or uninstalled.

The final setup keeps the stock packages enabled and uses the reference
launcher's existing `HomeKeyService` with `stock_home_redirect`. It does not
replace TCL's remote-button handling with custom key mappings.

## Launcher configuration used

These are the relevant values in `launcher/app/src/main/res/values/config.xml`:

```xml
<string name="stock_home_redirect" translatable="false">com.google.android.apps.tv.launcherx</string>
<bool name="key_filter">false</bool>
<bool name="restore_key_services">true</bool>
<string name="live_tv_package" translatable="false">com.tcl.tv</string>
<string name="live_tv_input_id" translatable="false">com.tcl.tvinput/.TDTVInputService/HW1413742848</string>
```

`HomeKeyService` was enabled; `key_filter=false` leaves key filtering off while
the service redirects stock Home to CleanYourTV. `restore_key_services=true`
was enabled with its required `WRITE_SECURE_SETTINGS` grant. These are existing
launcher options, not Java changes or changes to the defaults for other TVs.
See the [remote-key guidance](../../README.md#the-launcher) before enabling a
helper; configuring the values alone does not enable its accessibility service.

The dock includes `com.tcl.tv` as a normal app entry, labelled to distinguish
broadcast TV from internet channels. Dock
order and the other apps are household preferences, not requirements for this
firmware.

## Select terrestrial TV explicitly

The TV had an aerial cable connected, but it was also using TCL's internet
channels. Opening the TV app alone did not reliably select terrestrial TV.
The tuner input reported by `dumpsys tv_input` on this unit was
`com.tcl.tvinput/.TDTVInputService/HW1413742848`; it was used for
`live_tv_input_id` so the launcher can select the broadcast input explicitly.
Read the target TV's own input list before copying that value to other firmware.

Broadcast playback was observed and the terrestrial channel list could be
edited through TCL's normal UI. Live TV screenshots could be empty; an empty
capture was not sufficient evidence that playback or the tuner had failed.

## Validation limits and recovery

The owner confirmed the restored physical controls before the final launcher
configuration was reapplied. The final reference launcher and broadcast-TV
entry were exercised, but the complete remote-button matrix was not separately
repeated afterwards. The coloured teletext buttons, HDMI-CEC, casting, firmware
update delivery and long-term stability are not claimed as verified.

Separately, the owner reported intermittent full reboots during YouTube playback
with Home Assistant ADB polling enabled. Short playback checks without a reboot
did not establish a fix or identify its cause. Polling was ultimately left off
at the owner's request. This report makes no claim that the launcher configuration
fixes ADB availability, standby wake-up or those reboots.

Keep the original package and accessibility settings backup. If stock controls
regress, restore the packages changed in that session to their recorded states
and check the real remote before trying more mappings. To return to stock Home,
turn off CleanYourTV's Home helper in Android's accessibility settings and restore
the original Home selection. Do not overwrite other accessibility services while
undoing the helper. No factory reset, root or firmware flash was used here.
