# TCL 65C835 (`G05_4K_GB`, Italy): setupwraith stayed off, and 17 packages were gone before cleanup

One owner, one evening, Wi-Fi only. The full list below was applied with `tools/disable.sh` in batches with a
screenshot after each, the reference launcher went in with `launcher/build-and-install.sh`, and the set was
rebooted several times. Nobody has lived with it for days, so [CONTRIBUTING](../../CONTRIBUTING.md) makes this a note
and not a list: read it next to [`examples/tcl-65c735/`](../../examples/tcl-65c735/debloat.txt) and the
[55C728 note](tcl-55c728-g05-4k-gb.md), which are the same product and build ID.

## Identify the firmware, not the retail name

| Field | Value |
|---|---|
| Retail name | TCL 65C835, reports itself as `Smart TV Pro`, Italy |
| `ro.product.name` | `G05_4K_GB` |
| `ro.product.device` | `G05` |
| Android | Google TV on Android 11, SDK 30 |
| Build fingerprint | `TCL/G05_4K_GB/G05:11/AR2101/AR28:user/release-keys` |
| SoC | MediaTek `mt5889` |
| RAM | 2.7 GB |
| Network | Wi-Fi, no USB Ethernet adapter |

The fingerprint is identical to the 55C728 note's (`AR2101` / `AR28`), so the `65C735` list is the nearest
tested one. Most of this set's differences from it are the owner's choices and are marked as such below.

## What was done

A 39-package list, applied in the order below with a screenshot of Home between batches, then the launcher
(`launcher/build-and-install.sh` with `HOME_KEY_SERVICE=1`). `pm disable-user --user 0`, never `pm uninstall`.
13 of the 39 were already not installed for user 0 when the list ran (marked absent), so 26 packages were actually
disabled; see the next section.

this set gets no OTA updates until it is re-enabled. That was the owner's choice, not a recommendation.

## 17 packages were already gone for user 0 before the cleanup

The session started with 145 packages on the set and 128 of them installed for user 0: 17 were already
`installed=false` before the first command, removed for this user by whatever had been used on the set before
(it is not known what). `tools/disable.sh` writes its recovery record before it disables anything, and it
recorded the 13 of them that are in the list as `absent`. They are marked absent above; the other four are
`com.tcl.gallery`, `com.tcl.initsetup`, `com.tcl.keyhelp` and `com.tcl.inputmethod.international`.

What that means here:

- `pm disable-user` on such a package still answers `new state: disabled-user`, but it does not show in
  `pm list packages -d`, and `tools/check.py` lists it under "not installed any more". That is the state the set
  started in, not a disable that came undone.
- `tools/restore.sh` leaves `absent` packages alone, which is the right undo: it puts the set back as it was before
  the list. `pm enable` would not bring them back anyway; `pm install-existing --user 0 <pkg>` would.
- Three of the four are on the `65C735` list's do-not-disable line (`initsetup`, `keyhelp`, the TCL keyboard). This
  set worked without them: the remote, Input, HDMI, Wi-Fi, and typing with Google's keyboard.
- During testing, `com.tcl.guard` and `tv.wuaki.apptv` were put back with `pm install-existing --user 0` and then
  disabled again, so on this set they now read installed and disabled instead of absent.

## setupwraith and Home

- The saved Wi-Fi network belonged to `android.uid.system:1000`, not to setupwraith (`dumpsys wifi | grep -o
  'cname=[^ ]*'`), so `tools/disable.sh` let setupwraith go with no forget and re-join.
- The first `launcher/build-and-install.sh` run **rolled itself back**: after `launcherx` was disabled, Home
  resolved to `com.google.android.tungsten.setupwraith/.RecoveryActivity`, as the guard is written to expect. Disabling
  setupwraith and running the script again moved Home to `com.gathin.tvhome/.MainActivity`.
- Home, and every disable above, held across the reboots on `AR28`. This is the third `AR2101` report where
  setupwraith stayed off ([the 55C728 note](tcl-55c728-g05-4k-gb.md) has the table).

## Remote keys

- The gear button sends keycode `4077`, as on the other `G05_4K_GB` reports. With `launcherx` gone it does nothing
  until the launcher's `HomeKeyService` handles it: `settings_key_keycodes` `4077`, `HOME_KEY_SERVICE=1`.
  `settings_key_panel` makes it open the launcher's quick settings panel.
- The Input key worked with only `HomeKeyService` bound; `InputKeyService` was never enabled.
- Holding Volume+ still repeated with `HomeKeyService` bound, on the owner's real remote.
- The Netflix, YouTube and Prime Video buttons were left unmapped; those apps are off here.

## Other things seen

- The launcher's Wi-Fi pill read "Wi-Fi" and never showed the network name.
- Once, about four minutes after the second reboot, Home came back invisible after leaving an app: the paused app's
  last frame stayed on screen while the launcher kept answering the remote. It lasted about ten minutes across
  several launcher reinstalls, and then stopped. The same steps with unchanged code, with and without
  `advanced_effects`, and on a fresh boot, did not reproduce it afterwards, so the cause is **not known** and
  nothing here should be read as a fix. If you see it, `dumpsys activity activities | grep -E 'mResumedActivity|Task\{'`
  names the launcher as resumed while the screenshot shows the app.

## What was not tested

- Days of use, standby and wake, casting, Bluetooth pairing, and what a firmware update does to this list.
- Opening Live TV and switching HDMI inputs from the launcher's Inputs menu: the menu listed them, but the switch
  itself was not exercised on the TV.
- The three Netflix, YouTube and Prime Video remote buttons.
- Undo end to end: `restore.sh` was not run on this set.

Network ADB was left on at the owner's request for a home-automation tool. Port 5555 is plaintext; this firmware has
`ro.adb.secure=1`, so only an authorised computer gets a shell.
